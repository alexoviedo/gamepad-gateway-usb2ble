- Summary: I performed a comprehensive whole-codebase architecture hardening pass across the C++ firmware and JavaScript web application. The refactoring prioritizes boundary validation, stronger types, predictable schemas, and safer interface contracts.
- Subsystems audited: Firmware (BLE Config Service, Input Decoders, Mapping Engine, Shared Types, NVS Store) and Frontend Webapp (BLE Client JSON handlers).
- Major contract boundaries added: Added explicit parameter invariants for math transformations (deadzones, curves, normalization) in `mapping_engine.cpp` and `input_decoder.cpp`, including protections against divide-by-zero.
- Major type-safety improvements: Migrated weak C-style enums (`InputElementKind`, `HatDirection`, `DeviceRole`) to C++ `enum class` with explicit sizing, preventing loose integer assignment. Added C-compat fallback for headers.
- Major schema-validation improvements: Added a centralized `JsonExtractor` to strictly type-check and fallback default config shapes parsed from NVS/BLE in firmware. Added runtime schema validators (`validateDeviceSchema`, `validateEvtSchema`) in the Webapp to discard malformed inbound BLE payloads.
- Major interface-integrity improvements: Enforced maximum BLE configuration command payload boundaries to prevent memory pressure or buffer overruns. Replaced inline unstructured string dispatch with a strict typed `CmdHandler` dispatch table.
- Major composability improvements: The mapping engine's JSON parser now safely ignores missing fields without undefined behavior, relying heavily on cleanly extracted optional overrides.
- Files changed: `shared_types.h`, `input_elements.h/cpp`, `input_decoder.cpp`, `mapping_engine.cpp`, `hid_parser.cpp`, `ble_gamepad.cpp`, `ble_config_service.cpp`, `debug_portal.cpp`, `webapp/app.js`, `ARCHITECTURE_REFACTOR.md`.
- Tests added or updated: Verified against existing webapp test suite `app.test.js` covering JSON ingestion.
- Remaining weak spots: NVS read/write could still use a stronger serialization schema like Protocol Buffers or FlatBuffers rather than plain JSON for raw storage, but JSON is maintained for web compat.
- Recommended next hardening steps: Isolate `cJSON` entirely by migrating the frontend and backend protocol to a binary packed format to save MTU space and compute overhead. Add follow-me runtime config validators in the web app UI.
