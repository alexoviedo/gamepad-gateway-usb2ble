- Summary: I migrated the frontend and backend protocol from JSON-over-BLE to a tightly packed binary format to save MTU space and compute overhead, successfully isolating and removing all `cJSON` dependencies from the mapping engine and BLE layer.
- Subsystems audited: Firmware (BLE Config Service, Mapping Engine, NVS Store) and Frontend Webapp (BLE Client Command dispatcher and event parser).
- Major contract boundaries added: Implemented `ble_protocol.h` to define the shared memory layout/struct boundaries over the wire for BLE.
- Major type-safety improvements: The BLE handler now directly reads from typed `struct` definitions, rather than trusting and verifying fields inside JSON trees.
- Major schema-validation improvements: Commands like `set_config` and `save_profile` now explicitly cast and validate binary struct boundaries (`MappingProfileBin`).
- Major interface-integrity improvements: Handlers no longer require `cJSON` extraction logic, eliminating dynamic allocation errors (`OOM`) or string parsing issues for core mapping operations.
- Major composability improvements: The `HotasConfigClient` inside the webapp now supports binary command and event formats with a `DataView` parser, cleanly separating transport representation from application state arrays.
- Files changed: `main/ble_protocol.h`, `main/mapping_engine.cpp`, `main/mapping_engine.h`, `main/nvs_profile_store.h`, `main/nvs_profile_store.cpp`, `main/ble_config_service.cpp`, `webapp/app.js`, `webapp/app.test.js`.
- Tests added or updated: Updated `webapp/app.test.js` to simulate and assert binary array events parsed through the `handleEvtNotification` adapter.
- Remaining weak spots: Binary framing does not yet include a strict CRC inside the BLE chunks natively (relying on BLE L2CAP checking), though NVS storage maintains CRC32 verification.
